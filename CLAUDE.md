# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project
Interactive learning webapp that teaches students quality management (kwaliteitsmanagement). Part of the PXL Hogeschool "Projectmanagement" course series, next to AgileForNigel, TeachBertPERT and PMTheBasics.

## Requirements
- Single-page scroll layout (all sections on one page, nav links are anchor scrolls)
- Clean, modern design
- Max-width: 1100px (optimized for 1920x1080 student screens)

## Hosting — GitHub Pages
The site is published via GitHub Actions to GitHub Pages.

- **Workflow**: `.github/workflows/deploy.yml` — triggers on every push to `main`
- **Source setting**: GitHub Pages → Source must be set to **GitHub Actions** (in repo Settings → Pages)
- No build step — the entire repo root is uploaded as the Pages artifact
- `index.html` only redirects to `kwaliteit.html`, so the root URL works too
- **Gotcha:** Pushing workflow files requires the `workflow` OAuth scope. If rejected, add the file via GitHub web UI instead.

## Styling — PXL Hogeschool huisstijl
Same design tokens, typography, nav (hamburger + scroll spy), footer, badges and callouts as the sibling repos (see `../AgileForNigel/CLAUDE.md`).

**Extra tokens on this page:** every concept has a fixed color that is reused everywhere (cards, ladder rungs, quiz buttons, table headers, highlighter marks):
- `--c-doel` (black) = Doel
- `--c-ksf` / `--c-ksf-dark` (gold) = KSF
- `--c-kpi` (blue) = KPI
- `--c-target` (green) = Doelwaarde
- `--c-task` (grey) = gewone dagtaak

Key words in sentences are wrapped in `<mark class="hl-ksf|hl-kpi|hl-target">`; they get an animated highlighter stripe in the concept color.

## Language

Do NOT use em dashes (—, `&mdash;`, `—`) in any user-visible text. Use periods, colons, commas, or parentheses instead.

## Architecture
Single-file HTML page (`kwaliteit.html`) with inline `<style>` and `<script>` — no build step, no framework.

**Pattern:** data array → render function that rebuilds DOM via `innerHTML` → click handler updating global state → progress bar → summary card (`.summary.visible`) when everything is done.

**Current sections in `kwaliteit.html`:**
- `#ksf-kpi` — Kritische Succesfactoren & Kritische Prestatie-Indicatoren. Intro with 4 concept cards (Doel → KSF → KPI → Doelwaarde), each with an illustration on top (`img/concept_*.webp`, decorative, `alt=""`; the arrows between the cards sit at title height), then four parts:
  1. `#ksf-ladder` (prefix `ladder-`): "Beklim de KSF-ladder". The two lesson examples (restaurant, wasmachinefabrikant) in `LADDER_EXAMPLES[]`. Doel on top, one column per KSF with KPI/doelwaarde hidden until the student steps through. Every rung is its own button (`ladderRungClick(i, s)`): KSF selects the column, KPI and doelwaarde toggle, but always as a staircase (`ladderLevel[key]` = 1..3 is the visible level; hiding the KPI also hides the doelwaarde, and clicking a doelwaarde while the KPI is hidden only nudges it and shows a hint). The Vorige/Volgende buttons change the same level. `ladderVisited` (completion ✓) stays once a KSF reached level 3. Each step shows one sentence from the lesson's thinking frame ("Om het doel te bereiken is het noodzakelijk ... te hebben" / "De beste aanduiding ... is ..." / "We weten dat we op het goede spoor zijn indien ...") plus a note. `lowerBetter: true` marks KPIs where the target is a maximum. Artwork: each KSF has `art` (file in `img/ladder-*.webp`, 260px) shown at the right of the KSF rung (88px, 72px with four columns, hidden on phones) and at 48px next to the title of the explanation card; each example has `tabArt` (64px pictogram, shown at 26px in the tab). All decorative (`alt=""`). Ladder columns use `minmax(0, 1fr)` so long KSF names cannot widen a column.
  2. `#ksf-quiz` (prefix `quiz-`): sorter with 12 cards in 3 new contexts (`QUIZ_CONTEXTS`, `QUIZ_ITEMS`). Four answers: KSF, KPI, Doelwaarde, Dagtaak. The "dagtaak" category teaches that daily tasks are necessary but not critical. Hints depend on (chosen, correct) via `QUIZ_HINTS`. Layout follows `source/artwork-quiz/README.md`: a navigation of three situation groups (`QUIZ_GROUPS`, built from consecutive `ctx` in `QUIZ_ITEMS`; image + name + dots 1-4, dot colors green = first try, gold = after a hint, black = current with `aria-current="step"`), a scenario header with illustration (`QUIZ_CONTEXTS[ctx].art`, `img/quiz-situatie-*.webp`), name and goal, and a "Nieuwe situatie" banner (`quizBanner`) shown whenever navigation changes the situation (also going back or jumping) until the next interaction. Prev/next buttons announce a situation change ("Naar IT-helpdesk →", "← Terug naar Webshop"); `#quiz-announce` is an sr-only live region. The quiz box is a `div role="group"`, not a `section` (sections get page padding).
  3. `#ksf-campi` (prefix `campi-`): guided Campi exercise (same fictional project as in AgileForNigel's Planning Poker), following `source/artwork-campi/README.md`. Data stays in `CAMPI_CANDS` (8 candidates) and `CAMPI_KSFS` (4 KSF'en with KPI/doelwaarde options and the three course sentences). Three stages (`campiState.phase`: `select` → `work` → `summary`, tabs in `.campi-stages`): (1) pick 4 cards (`aria-pressed` buttons, max 4) and "Controleer mijn keuze"; feedback per chosen card; then "Werk de KSF'en uit" or "Selectie aanpassen". (2) One KSF at a time: KPI radios + "Controleer KPI", then "Kies een doelwaarde" + "Controleer doelwaarde", then the full reasoning. A KSF opens only when all earlier ones are complete (`campiCanOpen`); changing a checked KPI invalidates its doelwaarde. (3) Result table with a "Bekijk" button per row. State is saved in `localStorage` (`tijd-kwaliteit-campi-v1`, wrapped in try/catch); "Opnieuw oefenen" / "Voortgang wissen" ask for confirmation. The black goal box is sticky (top 62px) on screens wider than 760px. Decorative illustration `img/campi-campus.webp`. The panels are `div`s, not `section`s (sections get page padding).
  4. `#ksf-eigen` (prefix `own-`): free-form builder for the student's own project with live sentences and a simple checklist.
- `#kwaliteit-uitwerking` — Kwaliteit versus Uitwerking. Two definition cards (colors `--c-quality` orange, `--c-grade` purple), each with a decorative illustration at the top right of `.ku-def-head` (`img/ku-kwaliteit.webp` gear + magnifier, `img/ku-uitwerking.webp` multitool; 145px, 100px on phones), then:
  1. `#ku-burger` (prefix `burger-`, shared matrix classes `ku-`): two segmented toggles (kwaliteit/uitwerking hoog/laag) plus a clickable 2x2 matrix, synced. The hamburger from the lesson is shown as one of four photos (`img/burger_*.jpg`, file name per combination in `BURGER_COMBOS[k].img`). All four are stacked in `#burger-photo` and crossfade via the `.on` class. Texts per combination in `BURGER_COMBOS` (keys `'qu'`, e.g. `'10'` = hoge kwaliteit, lage uitwerking).
  2. `#ku-place` (prefix `place-`): 8 situations (`PLACE_ITEMS`, including Campi v1/v2) to place in the matrix. Hints name the wrong dimension. Reuses the `quiz-` card, dot and feedback styles.
- `#nauwkeurigheid-precisie` — Nauwkeurigheid versus precisie (prefix `np-`). Two definition cards (reuse `.ku-def`, colors `--c-accuracy` cyan, `--c-precision` magenta) with inline SVG target icons (no images), then:
  1. `#np-schijf`: the schietschijf from the lesson. Two segmented toggles (nauwkeurigheid/precisie hoog/laag, reusing the `burger-` classes) plus a 2x2 matrix with mini targets, synced. Texts per combination in `NP_COMBOS` (keys `'ap'`, `fig` = figure number in the lesson: '01' = 1, '10' = 2, '11' = 3, '00' = 4). `npShoot()` fires 8 animated shots (`npGenerate`: target radius 100, green zone 40; low accuracy = offset 55-62, low precision = ring spread 15-34 so '10' stays inside the green zone), with an overlay (mean cross, line to the centre = afwijking, dashed circle = spreiding) toggled by "Verberg metingen", and two meter bars. "Schiet opnieuw" draws a new random series. Mini targets use the seeded `npSeeded()` so they never change. Summary when all four combinations are visited.
  2. `#np-place` (prefix `npq-`): 8 measurement series (`NPQ_ITEMS`, values + ware waarde) to place in the matrix. Same pattern as `#ku-place`.
  3. `#np-spotify` (prefix `spot-`): the Spotify example from the lesson in 4 steps (`SPOT_STEPS`), made concrete with persona Lotte (20, studente in Hasselt) who mostly listens to international pop (`SPOT_HISTORY`): 10 pop recommendations (`SPOT_REC`, 8 saved, 2 skipped with a reason → precisie 8/10), 10 songs she found herself via TikTok, friends, radio, fuif (`SPOT_OTHER`, other genres → nauwkeurigheid 8/20), conclusion: Spotify stays in her filter bubble. Real, well-known songs for Belgian twenty-somethings; genre tags and cover colors via `SPOT_GENRES`. The precision bar shows the 95% KPI target. Ends with the lesson's conclusion as a callout.
- `#kosten-kwaliteit` — Kosten van kwaliteit (prefix `koq-`). Two cards "Investeren in kwaliteit" / "Besparen op kwaliteit" (colors `--c-invest` blue, `--c-fail` red; this pair was checked with the dataviz palette validator, the total line uses ink `--primary`). Each card has a decorative illustration at the right of `.koq-def-head` (`img/koq-investeren.webp` gear + clipboard + coins, `img/koq-besparen.webp` chipped gear + wrench + coins; 145x100px, 100x90px on phones, `alt=""`). Then:
  1. `#koq-balans`: interactive SVG chart (`initKoqChart`) of the classic cost-of-quality model with relative costs, no euros: `koqInvest(x)` rising, `koqFail(x)` falling, `koqTotal(x)` U-shaped with the minimum `KOQ_OPT` around x = 41. Slider, pointer and arrow keys set `koqSet(x)`; a marker with tooltip (hidden on phones) and a side panel show the three values, the zone (`KOQ_ZONES`: low < 25, mid 25-58, high > 58) and a Campi example. Summary when all three zones are visited.
  2. `#koq-sort`: 12 expenses (`KOQ_ITEMS`) sorted into "Investering in kwaliteit" vs "Kost van fouten", collected in two tally columns. Ends with a callout that links to the Poka Yoke section.
- `#poka-yoke` — Poka Yoke (prefix `py-`). Intro with the meaning of the name (poka + yoke(ru)) and Zero-Defects, then:
  1. `#py-rondom`: 8 flip cards (`PY_ITEMS`; `art` = `img/py-<naam>.webp` with `w`/`h`, shown 145x100px left-aligned above the title on the front (90px high on phones) and 52x42px next to the title on the back, `alt=""`) with everyday Poka Yoke's; the back names the prevented mistake and the kind (`prevent` = maakt de fout onmogelijk, `warn` = waarschuwt). Both faces share one CSS grid cell so the card grows with the longest face.
  2. `#py-checklist`: the garage checklist from the lesson (`PY_CHECKS`). The "Auto teruggeven" button uses `aria-disabled` (still clickable) so a click can highlight the missing steps; links to the Definition of Done.
  3. `#py-campi`: a Campi room-booking form with four toggleable Poka Yoke's (`PY_GUARDS`: date picker from today, end hour only after begin hour, room dropdowns, button lock). Room codes follow the real PXL format `DH.z<zone>v<verdiep>.<lokaal>` (e.g. DH.z2v02.23): zones 1-3, floors 00-02, rooms 01-25 (`PY_ZONES`, `PY_FLOORS`, `PY_NRS`). Without the guard the code is typed freely and `pyRoomProblem()` explains what is wrong; with the guard three dropdowns build the code. With the guards off, students make the four mistakes (`PY_ERRORS`: past, order, room, double = same booking twice within 4 s); with them on, the mistakes become impossible. Summary when all four were made and all four guards are on.
- `#visgraatdiagram` — Visgraatdiagram / Ishikawa (prefix `vg-`). Three fact cards (doel, werking, daarna), then:
  1. `#vg-anatomie`: the lesson's fishbone (effect 10/20, six categories) built up in 5 steps (`VG_ANAT_STEPS`: gevolg, ruggengraat, categorieën, oorzaken, suboorzaken), reusing the `spot-` stepper styles. Data in `VG_BONES` (bones end on the spine at `xe`, start 95px to the left; `vgBoneX(b, y)`). Lines draw with `pathLength="1"` + dashoffset; the current step is tinted gold. Sub-causes come from above on the top half and from below on the bottom half. Wrapped in `.vg-scroll` (min-width 760px) so phones scroll the diagram, not the page.
  2. `#vg-werkwijze`: five how-to steps (gevolg, brainstorm, groepeer, vraag door, prioriteer) plus a note on the 6 M's.
  3. `#vg-teken`: free drawing tool, inspired by the TeachBertPERT playground toolbar. **Deliberately generic**: only Selecteer, Lijn, Pijl, Kader, Afgerond, Ovaal, Tekst, Gom, Dun/Dik, Raster (grid 10px + 15° angle snap, Shift = free), Ongedaan/Opnieuw, PNG (cropped to the drawing, 2x), Bewaar/Open (JSON), Wis alles. No template and no fishbone-specific tools, so students must know the shape themselves. Shapes in `vg.shapes` (`line` with `a` arrow and `label`, `rect` with `round`, `ellipse`, `text`; `lw` thin/thick), rendered via `vgShapeSvg` with presentation attributes (needed for the PNG export). Inline text editor `#vg-editor` (Enter/Escape); double-click is detected in pointerdown because the shapes are re-rendered on the first click. The page-level pointerdown listener that tracks `vgActive` (keyboard shortcuts) runs in the capture phase for the same reason. A "Kladblok" side panel per case (`VG_CASES`: Campi, cafetaria, eigen probleem) lists brainstorm causes but no categories; click a note then the canvas (or drag it) to place it as text; used notes are struck through. Drawing + case are saved in `localStorage` (`tijd-kwaliteit-visgraat-v1`, try/catch). A short "Zo werkt de tool" guide (`.vg-help`, six generic how-to items, no fishbone hints) sits above the tool and a collapsed `<details>` self-check list below it.
- `#correlatiediagram` — Correlatiediagram (prefix `cor-`, color `--c-cor` blue for the dots, trend lines in `--c-ksf-dark`). Three cards (positief, negatief, geen) with seeded mini clouds, then:
  1. `#cor-lab`: 60 points (`COR_Z`: standardized, uncorrelated x and e, so y = r·x + √(1-r²)·e has exactly correlation r). Slider -1..1 and presets (`COR_PRESETS`, including a parabola). Points are `<g class="cor-pt">` moved with a CSS transform transition; they drop in when the chart first scrolls into view (IntersectionObserver). Panel shows r, an r scale, text per kind (`COR_LAB_TEXT`) and the four kinds visited (pos, neg, none, curve) → summary. Optional least-squares trend line.
  2. `#cor-cause`: the lesson's Internet Explorer vs murders example in 3 steps. The lesson's dual-axis chart is shown as two stacked timelines (no dual axes), then the murder dots morph into a scatter (x = IE share), then a red arrow shows the dots are simply ordered in time. Values read from the lesson figure (`COR_IE`, `COR_MURDER`).
  3. `#cor-oef`: the 7 lesson exercises, one at a time (`COR_EX`, `COR_EX_FN` with `chart`/`play`/`q` per exercise; `corExGo` renders the chart once and plays its animation, `corExRenderQ` only re-renders the question so animations do not restart; `corLater` timers are cleared on navigation). 1: 50 days of traffic dots appear one by one, trend line after the answer. 2: tickets week by week (data read from the lesson figure), guide line at x = 10 when C is chosen. 3: students click the 7 table points into a grid themselves (or let them be placed), then answer. 4: four clickable mini charts; the line y = ½x + 2 draws itself on the chosen chart. 5: wolves/deer counters and scatter (fictional numbers), two sub-questions. 6: 8 PXL pairs with expected direction (no wrong answer, compare with our expectation) plus a free "Bedenk er zelf een" list (not saved). 7: guide for hasselt.incijfers.be with reflection tips in `<details>` and a "done" checkbox. Shared helpers: `corFrame` (axes/grid, returns `px`/`py`), `corPearson`, `corFit`, `corNormals` (seeded via `npSeeded`), `corFmt` (nl-BE number format).
